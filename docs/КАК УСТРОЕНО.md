# Как устроен проект — по файлам и строкам

Слои снизу вверх: **config** → **srt_utils / media** → **transcribe / translate(_local)** → **pipeline** →
**runner** → три входа: **cli / watch / gui** → **упаковка**.

```
видео ──ffmpeg──▶ wav 16 kHz ──Whisper (MLX)──▶ слова с таймингами ──words_to_cues──▶ ru.srt
                                                                     │
                     Qwen (MLX) или Claude API, 1 реплика = 1 реплика ▼
                                                                  en.srt
                ┌───────────────────────────────┬──────────────────┘
       ffmpeg -c copy + mov_text          ffmpeg subtitles= (libass) + VideoToolbox
                ▼                                 ▼
        <имя>.subs.mp4                       <имя>.en.mp4
```

Все модели MLX живут в **одном потоке** (`transcribe._mlx_thread`): MLX привязывает GPU-stream
к потоку, где модель создана. Это главный неочевидный инвариант проекта.

## app/srt_utils.py — реплики и формат SRT (из оригинального бота, не менял)

| Строки | Что и зачем |
|---|---|
| 9–13 | Правила читаемости: реплика ≤ 6 с и ≤ 84 символов (2 строки по 42), ≥ 1 с, пауза ≥ 0,6 с — повод резать. |
| 16–28 | `Cue` — реплика (номер, начало, конец, текст). `Word` — слово с таймингом от Whisper. |
| 31–43 | Время ↔ `00:01:02,345`. `parse_ts` принимает и точку (VTT-стиль). |
| 46–60 | Перенос строк: перебирает все точки разреза и берёт самую сбалансированную пару строк. Если и так слишком длинно — обычный `textwrap`. |
| 63–64 | Конец фразы и конец части фразы — по пунктуации. |
| 67–100 | **Ресегментация.** Whisper даёт сегменты неудобной длины, поэтому реплики собираются заново из слов. Новая реплика начинается, если: пауза ≥ 0,6 с, реплика перевалит за 6 с или 84 символа, предыдущее слово закончило предложение (а набралось ≥ 20 символов) или часть фразы (≥ 55). |
| 103–113 | Слишком короткие реплики растягиваются до 1 с, плюс «хвост» 0,25 с, чтобы текст не исчезал мгновенно. На следующую реплику не залезает (−0,05 с). |
| 116–120 | Запись SRT, нумерация с 1. |
| 123–134 | Чтение SRT: BOM, `\r\n`, блоки без номера — для режима «положил готовый ru.srt → только перевод». |

| 25–34 | `ffprobe` в JSON. `has_video` не считает видео обложку в аудиофайле (`attached_pic`), иначе mp3 с картинкой пошёл бы в прожиг. |

Видео и звук копируются (`-c copy`) — без потерь и мгновенно. HEVC помечается `hvc1`, иначе QuickTime не откроет. Языки eng/rus, английская дорожка — по умолчанию. `0:v:0` — только основное видео: у iPhone бывают служебные дорожки. |
| 71–73 | Экранирование пути для фильтра `subtitles=` (двоеточия и кавычки ломают синтаксис фильтров ffmpeg). |
| 76–83 | Есть ли в этом ffmpeg фильтр или кодек — по выводу `-filters` / `-encoders`. |
| 86–111 | **Прожиг.** Без libass — понятная ошибка. Для вертикального кадра добавляется стиль `FontSize=11,MarginV=70`: в libass размер шрифта считается от высоты кадра, и на узком телефонном экране он выходит огромным; плюс текст поднимается над панелью Reels/TikTok. Кодирование — аппаратное `h264_videotoolbox`, при отказе — `libx264` (в раздаваемом ffmpeg его нет, там только VideoToolbox). |

## app/transcribe.py — Whisper

| Строки | Что и зачем |
|---|---|
| 17–21 | Модель одна на процесс, под замком. `_devnull` — для подавленного вывода tqdm. **`_mlx_thread`** — единственный поток для всего MLX (Whisper и переводчик): без этого падало «There is no Stream(gpu, 1) in current thread». |
| 24–28 | `get_model()` — загрузка в потоке MLX; вызывается при старте, чтобы первое видео не ждало. |
| 31–40 | `unload()` — выгрузить Whisper, когда на машине с 8 GB нужна память под переводчик. Чистим и наш указатель, и кэш `ModelHolder` внутри mlx-whisper, иначе память не освободится. |
| 43–68 | Загрузка: при `LOW_MEMORY` сначала выгружается переводчик. mlx-backend берёт модель через `ModelHolder` — тот же кэш, что использует `mlx_whisper.transcribe`, поэтому модель не грузится второй раз. faster-backend — код из оригинального бота для Intel. |
| 71–79 | Публичный интерфейс оригинала: `transcribe(audio, on_progress, hint) -> list[Cue]`. Слова → реплики через `words_to_cues`. |
| 82–88 | `importlib`, а не `import … as`: в `mlx_whisper/__init__` функция `transcribe` перекрывает одноимённый подмодуль. |
| 90–97 | Прогресс: mlx-whisper сообщает его только в tqdm, поэтому tqdm подменяется классом, который дёргает наш колбэк. |
| 98–104 | WAV читается сам и передаётся массивом: иначе mlx-whisper ищет `ffmpeg` в PATH, которого нет у приложений из Finder. |
| 105–115 | Параметры: русский, тайминги слов, без `condition_on_previous_text` (меньше зацикливаний), `initial_prompt` — первые 200 символов контекста (имена и термины), `hallucination_silence_threshold` — защита от «галлюцинаций» на тишине (VAD в mlx-whisper нет). |
| 116–122 | Сегменты → плоский список слов; сегмент без слов — одним «словом». |
| 125–146 | faster-whisper (Intel): то же самое плюс VAD и прогресс по времени сегмента. |

## app/translate.py — перевод через Claude (+ развилка на локальный)

| Строки | Что и зачем |

## Упаковка (`packaging/`)

**build_ffmpeg.sh** — свой ffmpeg для раздачи.
- 12–17: минимальная macOS 15.0 для всего; `pkg-config` видит только наши `.pc` — иначе подтянулись бы dylib Homebrew, которых у знакомых нет.
- 20–39: исходники с проверкой sha256.
- 52–57: freetype без модуля hvf (`libhvf` есть только с macOS 15.4 — та самая поломка ffmpeg-full).
- 59–71: fribidi и harfbuzz — для правильной вёрстки текста; libass — **через CoreText**, без fontconfig: шрифты берутся системные, кириллица работает из коробки.
- 73–81: ffmpeg статически, `--disable-autodetect` (ничего лишнего не подцепится), без сети и без GPL-кодеков → лицензия LGPL, можно раздавать.

**build_app.sh** — сборка `.app` и zip.
- 9–23: ffmpeg (если ещё нет), `uv`, Python 3.12 из python-build-standalone (не зависит от Homebrew), зависимости **под macOS 15** (без `MACOSX_DEPLOYMENT_TARGET` uv брал mlx под 26.x). mlx-whisper ставится `--no-deps`, чтобы не тянуть torch (~1 GB).
- 25–30: иконка, PyInstaller (промежуточное — в `packaging/build/dist`), ad-hoc подпись.
- 32–38: проверка, что ни один бинарник в `.app` не требует macOS новее 15.0, иначе сборка падает.
- 39–52: в корень проекта — `Субтитры.app` и «Как установить.txt»; zip — папка «Субтитры» (приложение + оба гайда) без служебных `._*`.

**subtitles.spec** — что класть в `.app`.
- 9–14: целиком пакеты, которые грузят код и данные динамически (mlx — `metallib`, mlx_lm — архитектуры моделей по имени, hf_xet — быстрая загрузка моделей), плюс наш ffmpeg в `bin/`.
- 21–24: неочевидные импорты и исключения (torch, tensorflow и т. п. — тяжёлые и не нужны).
- 27–48: exe `Subtitles`, бандл `Субтитры.app` (обычное приложение: окно + Dock), минимум macOS 15, `CFBundleDocumentTypes` — чтобы macOS разрешала бросать видео на иконку.

**entry.py** — точка входа. `freeze_support()` обязателен: tqdm заводит multiprocessing-lock, `resource_tracker` перезапускает тот же exe, и без этого вызова поднимался второй экземпляр приложения.

**make_icon.py** — иконка: градиент + SF Symbol, все размеры → `iconutil` → `.icns`.

**requirements-app.txt** — точные версии зависимостей `.app`. Гайды для пользователей (`docs/Как установить.txt`, `docs/Как пользоваться.txt`) сборка кладёт в zip, а «Как установить» — ещё и в корень рядом с приложением.

## Остальное

- `Субтитры.app`, `Субтитры.zip`, `Как установить.txt` — готовый результат, их кладёт `build_app.sh`.
- `.env` — настройки dev-версии: ключ, `TRANSLATOR`, модели, прожиг.
- `requirements.txt` — зависимости dev-версии.
- `dev/` — рабочие папки dev-версии (`inbox`, `done`, `failed`, `logs`, `models`, `.work`); путь задаёт `config.py`.
- `tools/Сделать субтитры.command` — двойной клик → `python -m app.watch` в Терминале.
- `tools/make_quick_action.py` — Quick Action для dev-версии (через `app.cli`, а не через `.app`).
- `test/` — `test.mp4` (синтезированная речь) и `bench.ru.srt` (30 реплик для сравнения переводчиков).
- `packaging/build/` — кэш сборки (Python, ffmpeg, PyInstaller; можно удалить, пересоберётся).
