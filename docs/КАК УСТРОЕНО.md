# Как устроен проект — по файлам и строкам

Слои снизу вверх: **config** → **srt_utils / media** → **transcribe / translate(_local)** → **pipeline** →
**runner** → три входа: **cli / watch / gui** → **упаковка**.

```
видео ──ffmpeg──▶ wav 16 kHz ──Whisper (MLX)──▶ слова с таймингами ──words_to_cues──▶ ru.srt
                                                                     │
                     Qwen (MLX) или Claude API, 1 реплика = 1 реплика ▼
                                                                  en.srt
                ┌───────────────────────────────┬──────────────────┘
       ffmpeg -c copy + mov_text          ffmpeg subtitles= (libass) + VideoToolbox
                ▼                                 ▼
        <имя>.subs.mp4                       <имя>.en.mp4
```

Все модели MLX живут в **одном потоке** (`transcribe._mlx_thread`): MLX привязывает GPU-stream
к потоку, где модель создана. Это главный неочевидный инвариант проекта.

## app/srt_utils.py — реплики и формат SRT (из оригинального бота)

| Строки | Что и зачем |
|---|---|
| 9–13 | Правила читаемости: реплика ≤ 6 с и ≤ 84 символов (2 строки по 42), ≥ 1 с, пауза ≥ 0,6 с — повод резать. |
| 16–30 | `Word` — слово с таймингом и уверенностью (`prob`) от Whisper: по ней редактор подсвечивает сомнительные слова. `Cue` — реплика (номер, начало, конец, текст) и **её слова**: раньше они выбрасывались, теперь нужны для подсветки слова и «N слов на экране». |
| 32–44 | Время ↔ `00:01:02,345`. `parse_ts` принимает и точку (VTT-стиль). |
| 47–61 | Перенос строк: перебирает все точки разреза и берёт самую сбалансированную пару строк. Если и так слишком длинно — обычный `textwrap`. |
| 64–65 | Конец фразы и конец части фразы — по пунктуации. |
| 68–102 | **Ресегментация.** Whisper даёт сегменты неудобной длины, поэтому реплики собираются заново из слов. Новая реплика начинается, если: пауза ≥ 0,6 с, реплика перевалит за 6 с или 84 символа, предыдущее слово закончило предложение (а набралось ≥ 20 символов) или часть фразы (≥ 55). |
| 105–115 | Слишком короткие реплики растягиваются до 1 с, плюс «хвост» 0,25 с, чтобы текст не исчезал мгновенно. На следующую реплику не залезает (−0,05 с). |
| 119–126 | `apply_fixes` — замены, запомненные в редакторе (`fixes.json`): подстрокой и без регистра, как «Заменить» в редакторе, чтобы ловить падежи. Конвейер делает их после распознавания и после перевода. |
| 129–133 | Запись SRT, нумерация с 1. |
| 136–147 | Чтение SRT: BOM, `\r\n`, блоки без номера — для режима «положил готовый ru.srt → только перевод». |

## app/media.py — всё, что делает ffmpeg

| Строки | Что и зачем |
|---|---|
| 14–24 | Запуск процесса асинхронно. В «Экономе» — через `taskpolicy -c utility`: QoS потока дочерний процесс не наследует. При ошибке — последние 1500 символов stderr в исключение: в `error.txt` видно, что сказал ffmpeg. |
| 27–36 | `ffprobe` в JSON. `has_video` не считает видео обложку в аудиофайле (`attached_pic`), иначе mp3 с картинкой пошёл бы в прожиг. |
| 39–43 | Звук → 16 kHz моно PCM: ровно то, что ест Whisper, без пересэмплирования внутри. |
| 46–66 | **Где звучит голос.** Whisper тянет слова через паузы, поэтому паузы ищем сами по энергии 200–3500 Гц кадрами по 20 мс. Порог — от уровня самой записи (10-й и 95-й перцентили): тихий микрофон и музыка фоном не ломают его. Провалы короче 200 мс — между слогами, не пауза. На 87 с видео — 0,07 с. |
| 69–71 | Какие кодеки QuickTime и iPhone играют из MP4 без перекодирования. |
| 71–90 | **Видео с отключаемыми субтитрами.** Смотрим кодеки исходника: h264/hevc + aac/mp3/alac/ac3 → MP4 с дорожками `mov_text` (QuickTime → Вид → Субтитры); иначе MKV с `srt` (IINA/VLC). Видео и звук копируются (`-c copy`) — без потерь и мгновенно. HEVC помечается `hvc1`, иначе QuickTime не откроет. Языки eng/rus, английская дорожка — по умолчанию. `0:v:0` — только основное видео: у iPhone бывают служебные дорожки. |
| 93–95 | Экранирование пути для фильтра `subtitles=` (двоеточия и кавычки ломают синтаксис фильтров ffmpeg). |
| 98–105 | Есть ли в этом ffmpeg фильтр или кодек — по выводу `-filters` / `-encoders`. |
| 108–131 | **Прожиг.** Без libass — понятная ошибка. Субтитры — ASS, собранный из пресета (`app/style.py`), шрифты — свои из `fontsdir`: тот же рендер, что в превью редактора, поэтому `force_style` и отдельная добавка для вертикали больше не нужны. Берём только картинку и звук (`-map 0:v:0 -map 0:a:0?`): при пересборке исходником бывает копия с дорожками субтитров. Кодирование — аппаратное `h264_videotoolbox`, при отказе — `libx264` (в раздаваемом ffmpeg его нет, там только VideoToolbox). |

## app/transcribe.py — Whisper

| Строки | Что и зачем |
|---|---|

| 62–67 | `release()` — выгрузить обе модели в потоке MLX: после простоя (`watch.serve`) и при смене нагрузки. |

| 103–111 | Публичный интерфейс оригинала: `transcribe(audio, on_progress, hint) -> list[Cue]`. Слова → реплики через `words_to_cues`. |

| 137–138 | WAV читается сам и передаётся массивом: иначе mlx-whisper ищет `ffmpeg` в PATH, которого нет у приложений из Finder. |
| 139–149 | Параметры: русский, тайминги слов, без `condition_on_previous_text` (меньше зацикливаний), `initial_prompt` — первые 200 символов контекста (имена и термины), `hallucination_silence_threshold` — защита от «галлюцинаций» на тишине (VAD в mlx-whisper нет). |
| 150–156 | Сегменты → плоский список слов; сегмент без слов — одним «словом». |
| 159–180 | faster-whisper (Intel): то же самое плюс VAD и прогресс по времени сегмента. |

**kadr.spec** — что класть в `.app`.
- 9–14: целиком пакеты, которые грузят код и данные динамически (mlx — `metallib`, mlx_lm — архитектуры моделей по имени, hf_xet — быстрая загрузка моделей), плюс наш ffmpeg в `bin/`.

**vendor_jassub.sh** — пересобрать `app/editor/vendor/jassub` из npm: версии закреплены, install-скрипты не запускаются, esbuild собирает основной модуль и воркер в два файла.

**make_icon.py** — иконка: градиент + SF Symbol, все размеры → `iconutil` → `.icns`.

**requirements-app.txt** — точные версии зависимостей `.app`. Гайды для пользователей (`docs/Как установить.txt`, `docs/Как пользоваться.txt`) сборка кладёт в zip, а «Как установить» — ещё и в корень рядом с приложением.

## Остальное

- `Kadr.app`, `Kadr.zip`, `Как установить.txt` — готовый результат, их кладёт `build_app.sh`.
- `.env` — настройки dev-версии: ключ, `TRANSLATOR`, модели, прожиг.
- `requirements.txt` — зависимости dev-версии.
- `dev/` — рабочие папки dev-версии (`inbox`, `done`, `failed`, `logs`, `models`, `.work`); путь задаёт `config.py`.
- `tools/Сделать субтитры.command` — двойной клик → `python -m app.watch` в Терминале.
- `tools/make_quick_action.py` — Quick Action для dev-версии (через `app.cli`, а не через `.app`).
- `test/` — `test.mp4` (синтезированная речь) и `bench.ru.srt` (30 реплик для сравнения переводчиков).
- `packaging/build/` — кэш сборки (Python, ffmpeg, PyInstaller; можно удалить, пересоберётся).
